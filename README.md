## 🧠 Core Expertise

I build **AI-powered products that ship**: end to end, from the data model to the deployed URL. My focus is the applied layer of AI: turning an LLM API into a system that is fast, cheap per request, and predictable enough to put in front of paying users.

I care about the boring parts that decide whether a product survives: **cost per request, p95 latency, retry and fallback logic, and output validation**, because a generation that is 5% better but 3× more expensive is not an improvement. Everything I build gets deployed and used, not left in a notebook: real-time multiplayer on AWS, Telegram WebApps with live users, and a game economy tuned with Monte Carlo simulation.

Currently freelancing under the **XSUGL Dev** brand and starting **Computer Engineering & Artificial Intelligence @ Università Roma Tre** in October 2026. Long-term target: AI engineering in production, at scale.

## 🚀 Featured Projects

### ⚔️ Battle With Friends: real-time multiplayer arena
> Browser-based PvP arena with authoritative server, persistent accounts and match history. Built as my diploma capstone and defended at the Maturità oral exam.

`Node.js` `WebSocket` `MariaDB` `JWT` `Canvas API` `AWS EC2`

**Engineering challenge:** keeping every client visually in sync over an unreliable network without letting the client decide anything. Solved by making the server the sole authority over game state, streaming deltas rather than full snapshots, and reconciling client-side prediction against server ticks so lag shows up as a small correction instead of a teleport.

### ⛏️ PixaxeSlot: slot-mechanic game with a simulated economy
> A pickaxe/block-themed betting game built on a multi-game platform, with the entire payout model designed in simulation before implementation. Monetisation via TON, Telegram Stars and gifts.

`JavaScript` `Node.js` `Monte Carlo Simulation` `Telegram WebApp` `TON`

**Engineering challenge:** you cannot A/B test a game economy on real money without burning real money. I wrote a seeded simulation toolchain (`econ-sessions`, `econ-odds`) that replays millions of sessions against the payout tables, so RTP, house margin and session-level distributions were known constants before launch, and any tweak to a block's payout can be re-validated in seconds.
